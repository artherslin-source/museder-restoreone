# WordPress 外掛安裝突然失敗診斷指南

## 問題說明

同一個網站之前可以正常安裝外掛，但現在突然失敗。這通常表示系統環境發生了變化。

## 可能原因和檢查方法

### 1. 磁盤空間不足

**檢查方法：**
- 通過 cPanel：查看「磁盤使用量」
- 通過 SSH（如果可用）：
  ```bash
  df -h
  ```
- 通過 FTP：檢查是否有足夠空間

**解決方案：**
- 清理不需要的文件
- 刪除舊的備份文件
- 清理臨時文件
- 聯繫主機服務商增加空間

### 2. 臨時目錄被清理或刪除

**檢查方法：**
- 檢查 `wp-content/tmp` 是否存在
- 檢查系統臨時目錄（`/tmp`）是否可寫入

**解決方案：**
- 重新創建臨時目錄
- 在 `wp-config.php` 中定義 `WP_TEMP_DIR`

### 3. 文件權限被改變

**檢查方法：**
- 通過 FTP 檢查 `wp-content/plugins/` 目錄權限
- 檢查目錄擁有者是否改變

**解決方案：**
- 修正目錄權限為 `755`
- 確保擁有者是網站運行用戶

### 4. PHP 配置改變

**檢查方法：**
- 檢查 PHP 的 `upload_max_filesize` 和 `post_max_size`
- 檢查 `upload_tmp_dir` 設置

**解決方案：**
- 通過 cPanel 檢查 PHP 配置
- 聯繫主機服務商檢查是否有配置變更

### 5. 服務器資源限制

**檢查方法：**
- 檢查 PHP 內存限制
- 檢查執行時間限制
- 檢查服務器負載

**解決方案：**
- 增加 PHP 內存限制
- 增加執行時間限制
- 聯繫主機服務商檢查服務器狀態

### 6. 文件系統問題

**檢查方法：**
- 檢查文件系統是否只讀
- 檢查是否有文件系統錯誤

**解決方案：**
- 聯繫主機服務商檢查文件系統
- 可能需要重啟服務器

## 快速診斷步驟

### 步驟 1：檢查磁盤空間

1. 登入 cPanel
2. 查看「磁盤使用量」
3. 如果空間不足，清理文件

### 步驟 2：檢查臨時目錄

1. 通過 FTP 或 cPanel 文件管理器
2. 檢查 `wp-content/tmp` 是否存在
3. 如果不存在，創建它並設置權限為 `755`

### 步驟 3：檢查文件權限

1. 通過 FTP 檢查 `wp-content/plugins/` 目錄
2. 確認權限為 `755`
3. 確認擁有者正確

### 步驟 4：檢查 PHP 配置

1. 在 WordPress 根目錄創建 `phpinfo.php`：
   ```php
   <?php phpinfo(); ?>
   ```
2. 訪問 `yoursite.com/phpinfo.php`
3. 檢查以下設置：
   - `upload_max_filesize`
   - `post_max_size`
   - `upload_tmp_dir`
   - `memory_limit`
4. **重要：** 檢查完後立即刪除 `phpinfo.php` 文件

### 步驟 5：檢查錯誤日誌

1. 通過 cPanel 查看錯誤日誌
2. 檢查是否有相關錯誤訊息
3. 查看 WordPress 調試日誌（如果啟用）

## 臨時解決方案

如果無法立即修復問題，可以使用手動上傳方式：

1. **下載外掛 ZIP 文件**
2. **解壓縮到本地電腦**
3. **通過 FTP 上傳到 `wp-content/plugins/`**
4. **在 WordPress 後台啟用外掛**

## 聯繫主機服務商

如果以上方法都無法解決，建議聯繫主機服務商，並提供以下信息：

1. **錯誤訊息：** "無法複製檔案。museder-restoreone/includes/class-dashboard.php"
2. **發生時間：** 一個小時前還可以，現在不行
3. **已檢查項目：**
   - 磁盤空間：XXX MB 可用
   - 文件權限：已檢查
   - PHP 配置：已檢查
4. **請求協助：**
   - 檢查服務器是否有配置變更
   - 檢查文件系統狀態
   - 檢查服務器資源使用情況

## 預防措施

1. **定期檢查磁盤空間**
2. **定期清理臨時文件**
3. **備份重要文件**
4. **監控服務器狀態**
